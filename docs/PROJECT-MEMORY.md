# Finplot 项目记忆

## 产品目标

打造一个让个人能快速看懂自己财务状态、收支结构、结余趋势和投资表现的 Web 应用。它应当像一个清晰、可信、安静的个人工具，而不是工程后台或传统报表系统。

## 已确认的设计方向

- 品牌方向：澄明 Folio；克制、清晰、可信、有 Apple 产品的秩序感。
- 信息顺序：状态 → 变化 → 结构 → 明细。
- 首页默认突出结余、收入、支出和收支趋势；分析页再进入类别结构；投资页单独处理收益与持仓。
- 使用浅灰背景、白色表面、柔和分隔线和蓝色交互强调；颜色只承担语义，不用颜色单独传达收入或支出。
- 通过排版、比例和留白建立层级，避免厚重阴影、深色卡片墙、重复的大标题和无意义的巨大空白。
- 图表必须支持判断：有清晰的时间、数量、单位和比较关系；不使用装饰性假图。
- 桌面端使用并排关系帮助比较，窄屏端恢复顺序阅读，不产生整页横向滚动。

## 对旧方案的纠偏

九个功能模块不应在首页被做成九张同等重量的卡片；通用模板不能覆盖页面目标；筛选不应占据大面积却只提供几个控件；支出页不应重复展示无关的收入指标；图表不能用密集小卡补救不可读的尺度。

## 数据口径注意事项

- 备份中的交易金额是正数，方向字段决定收入或支出。
- `nature` 可以区分日常、投资、往来和调整；分析页需要明确是否排除往来与调整。
- 投资页必须先确认产品要展示已实现收益、浮动收益、持仓市值，还是三者分开；设计原型中的投资持仓数字是示例，不是已确认业务口径。
- 类别、分类组和别名均由数据库提供；前端不应复制一份静态分类规则作为唯一来源。
- `source_record_id` 用于去重和追溯来源，相关交易页应保留来源信息筛选能力。

## 工作方式

每次扩展先明确页面要回答的问题和数据口径，再决定指标、图表和明细。实现后在 1440px 和 390px 下对照设计稿，检查比例、文字换行、长数字、空数据、无匹配、错误和键盘焦点。不要因为功能增加而恢复成密集后台布局。

## 真实页面实施更新

已沿用设计原型样式实现总览、收支分析、分类交易展开、全部交易和投资记录。月份/年度、性质、方向筛选统一作用于指标和明细；趋势展示所选年度。默认日常可切换全部或单一性质，未将默认值视作已确认业务口径。投资页不提供虚构持仓与收益率。

服务入口 `python3 app/server.py`，端口 8765；仅允许公开 index.html、app.js 与只读 API，禁止目录浏览。真实记录由本地 API 动态读取，前端以整数分聚合；没有静态打包私人数据。当前为本地原型，正式服务与部署技术栈尚待确定。

验证：1440px/390px 页面导航、无横向溢出、年度切换、收入分类、分类展开、隐私隐藏及空数据通过浏览器自动化检查。桌面截图已检查。服务重启后本机及 Tailscale 地址可访问。尚未配置开机自启，主机休眠时无法保证远程访问；时间时区、投资会计口径仍待确认。

数据库定位与启动：`app/ledger.py` 优先读取显式参数和 `FINPLOT_DATABASE`，否则自动发现 `data/` 中唯一的 SQLite 文件；发现多个或没有文件时明确报错，不静默猜测。根目录 `启动Finplot.command` 可在 macOS 双击启动服务并打开浏览器。数据库文件仍不会进入 Git。

数据库路径体验更新：macOS 启动文件首次找不到数据库时调用系统文件选择器，选中的路径保存到被 Git 忽略的 `.finplot-database`；后续双击自动复用。网页不直接承担本机任意路径选择，避免浏览器安全限制。
